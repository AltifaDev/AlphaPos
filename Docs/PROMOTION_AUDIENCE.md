# ช่องทางโปรโมชั่นและส่วนลดพนักงาน

หน้าโปรโมชั่นเดิมบันทึกแล้วเรียกซิงก์เมนูและโปรโมชั่นทันที ไม่มีตัวแยกช่องทาง แบนเนอร์ไม่ได้เป็นเงื่อนไขการคำนวณส่วนลด แต่ขั้นตอนบันทึกผูกกับการเผยแพร่เว็บ

เพิ่มตัวเลือกในฟอร์ม:

- **ลูกค้า · เผยแพร่บนเว็บ**: ทำงานแบบเดิม พร้อมรูป/วิดีโอได้ โปรโมชั่นเดิมยังอยู่ในกลุ่มนี้
- **ลูกค้า · เฉพาะ POS**: บันทึกนิยามโปรโมชั่นในเครื่อง ใช้คำนวณส่วนลดตามเดิม ไม่ส่งนิยามหรือแบนเนอร์ไปเซิร์ฟเวอร์
- **พนักงาน · เฉพาะ POS**: กำหนดจำนวนเงินหรือเปอร์เซ็นต์ได้ รวมถึงยอดขั้นต่ำและช่วงเวลา เลือกใช้ที่ POS เอง ไม่เข้าการเลือกส่วนลดอัตโนมัติ

แพ็กเกจออฟไลน์หรือโหมดออฟไลน์ซ่อนช่องทางเว็บและแบนเนอร์ บันทึกได้โดยไม่รอเครือข่าย และไม่ดึง/อัปโหลดโปรโมชั่นหรือชุดสินค้าโปรโมชั่น การลบเก็บสถานะในเครื่องไว้สำหรับประวัติและการซิงก์ภายหลัง

ส่วนลดเฉพาะ POS และพนักงานเก็บเฉพาะเครื่องที่สร้าง ไม่กระจายไปเครื่องอื่น ตัวเลขส่วนลดของบิลยังอยู่ในรายงานและซิงก์บัญชีตามโหมดปกติ โดยไม่อ้างอิง foreign key ของโปรโมชั่นที่ไม่มีในเซิร์ฟเวอร์ บันทึกเหตุผล Staff discount สำหรับบิลพนักงาน

เมื่อเปลี่ยนโปรโมชั่นที่เคยเผยแพร่เป็นภายในร้าน จะคงนิยามในเครื่องและตั้งคิวถอนรายการเดิมบนเว็บ การถอนต้องเชื่อมต่อสำเร็จ; ฟอร์มและการ์ดแสดงสถานะรอถอน ไม่สามารถถอนข้อมูลที่เผยแพร่ไปแล้วขณะไม่มีอินเทอร์เน็ตได้ หน้าเว็บที่เปิดค้าง/แคชไว้อาจยังแสดงข้อมูลเก่าจนโหลดข้อมูลใหม่

## ตรวจสอบ

`python3 scripts/test_promotion_scope.py` ทดสอบตรรกะจาก Promotion.swift โดยเอาเฉพาะ annotation ของ SwiftData ออกจากสำเนาชั่วคราว: ค่าเริ่มต้นเดิม, ช่องทางภายใน, ส่วนลดพนักงานไม่ใช้เองอัตโนมัติ, เปอร์เซ็นต์, จำนวนเงิน, เพดานยอดบิล, ยอดขั้นต่ำ, วันสิ้นสุด, เปิด/ปิด, ลบ และจำนวนสิทธิ์

ตรวจไวยากรณ์ไฟล์ Swift ที่แก้แล้วด้วย `swiftc -frontend -parse` ผ่าน แต่เครื่องที่ทำงานนี้ไม่มี Xcode และ SwiftData macro plugin จึงยังไม่ยืนยันบิลด์ iOS, การ migrate ฐานข้อมูลจริง หรือหน้าจอจริง

ทดสอบบน Xcode/iPad ก่อนออกเวอร์ชัน:

1. เปิดฐานข้อมูลเดิม ตรวจโปรโมชั่นเดิมยังมีข้อมูลครบและเป็นช่องทางเว็บ
2. เปิดแพ็กเกจออฟไลน์ สร้างส่วนลดทั้งบาท/เปอร์เซ็นต์โดยไม่มีสื่อ บันทึก ปิดเปิดแอป และชำระบิล ตรวจยอดและรายงาน
3. สร้างส่วนลดพนักงานที่สูงกว่าของลูกค้า ตรวจระบบอัตโนมัติไม่เลือกพนักงาน จากนั้นเลือกเองและตรวจยอด/เหตุผลในรายงาน
4. ตรวจเว็บและ network ว่าไม่มีการอัปโหลดนิยามหรือสื่อของโปรโมชั่นภายในร้าน
5. เปลี่ยนโปรโมชั่นเว็บเดิมเป็นภายในร้านระหว่างออฟไลน์ ตรวจคิวถอน หลังออนไลน์ซิงก์สำเร็จ ตรวจไม่ปรากฏในเว็บที่โหลดข้อมูลใหม่ และนิยามในเครื่องยังคงอยู่
6. ซิงก์บิลที่ใช้ส่วนลดภายในร้าน ตรวจบันทึก OrderDiscount สำเร็จโดยไม่มี promotion_id และยอดขายตรงกับเครื่อง
